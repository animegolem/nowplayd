* 1. Summary

nowplayd is a standalone Rust daemon that connects to MPD as a peer
client — never a frontend plugin — and publishes playback state to
macOS Now Playing (=MPNowPlayingInfoCenter=) while handling remote
commands (=MPRemoteCommandCenter=). Every MPD frontend benefits
equally. Status: platform architecture gate PASSED (rev 0.5, spike
merged at =spike/=); production daemon implementation proceeds one
ticket at a time under per-ticket owner authorization (§6, rev 0.6);
no production code yet.

* 2. Motivation

macOS media keys, Control Center, lock screen, and AirPods gestures
are arbitrated by =mediaremoted=, which routes only to apps registered
through the MediaPlayer framework. Terminal frontends structurally
cannot register. MPD holds all playback state, so a small bridge
daemon closes the gap for every frontend at once. No modern standalone
tool does this (osxmpdkeys is a 2012-era raw event tap; native GUI
clients bundle the integration into the frontend).

* 3. Goals and non-goals

** 3.1 Goals
- Hardware media keys and system surfaces control MPD.
- Now Playing shows metadata + album art promptly (bounds: §7).
- Zero-config default; survives MPD restarts and login sessions.

** 3.2 Non-goals
- Not an MPD frontend: no UI, no library browsing, no queue editing.
- Not an rmpc/rmpcd plugin (rev 0.2 ruling, see §10).
- No scrobbling, notifications, or theming — other tools own those.
- Seek and volume remote commands: deferred, not v1 (see §9). The
  scrubber capability is actively disabled, not silently accepted
  (rev 0.3, §9).

* 4. Core invariants

- Peer MPD client over the wire protocol; event-driven via =idle= —
  no polling loops, idle CPU near zero.
- Platform layer (as amended rev 0.3): =souvlaki= PLUS the smallest
  target-gated macOS shim needed for (a) true Now Playing clearing
  (assigning nil to =nowPlayingInfo=, which souvlaki's public API
  cannot do) and (b) remote-command capability control (disabling
  =changePlaybackPositionCommand=, which souvlaki enables
  unconditionally). No other direct MediaPlayer bindings without a
  further amendment. Original rev 0.1 wording ("souvlaki is the only
  platform-integration surface") is superseded by this clause.
  MPRIS on Linux remains a side effect; that leg must keep compiling
  but is CI-level validated only.
- Single small binary; no runtime dependencies beyond MPD.
- Rust 2024. Gates: =cargo build= / =cargo test= /
  =cargo clippy -- -D warnings=.
- macOS media-layer behavior that cannot be validated headless is
  flagged to =RAG/HUMAN-TESTING.md=, never claimed verified. Human
  tests must state preconditions for competing Now Playing sessions
  (Music.app, Spotify) (rev 0.3).

* 5. Architecture

** 5.1 Connection model (ruled rev 0.3; framing amended rev 0.4)
TWO MPD connections: a dedicated idle listener (=idle player mixer
options=) and a separate command/query connection for
=status=/=currentsong=/artwork reads and command writes. This removes
the =noidle= cancellation dance from the design; tickets must not
reintroduce a single-connection model without amendment. Default
address =localhost:6600=; unix sockets and password supported (§11
FR-7).

Wire framing is NOT hand-rolled (rev 0.4, Sol round-1 amendment 3):
=mpd_protocol= 1.0.3 =AsyncConnection= owns greeting, escaping,
OK/ACK, partial reads, and binary frames; =mpd_client= 1.4.1 typed
=Command= definitions may be used on top, but its full =Client= loop
(automatic idle/noidle) must not be, as it conflicts with this
section. Project-local protocol code is limited to mapping
framed/typed responses into =PlayerState= and project error types.

Command-connection fairness (rev 0.4): the command/query connection
owner yields between artwork chunks and services pending remote
commands and state refreshes before the next art chunk; no exclusive
borrow may span an entire art fetch.

Command-role liveness (ruled rev 0.10 — found by the M3 live gate:
MPD's default =connection_timeout= reaps inactive clients after 60 s
while =idle= waiters are exempt, so the quiet command role dies
between events): the command role is revalidated AT USE, entirely
event-driven — no timers, preserving §4.

- Staleness check: at each command-role operation, if the socket has
  been quiet longer than a threshold below MPD's floor (50 s against
  the 60 s default), first =ping=; on ping failure, reconnect (+
  re-auth) before issuing the operation. A timestamp compared at use
  time, never a scheduled wakeup.
- Non-mutating operations (=ping=, =status=/=currentsong= refresh,
  artwork reads) MAY reconnect-and-retry once on a transport error.
- MUTATING remote commands are NEVER blindly retried after a
  mid-flight transport error — the command may already have executed
  (a retried =next= double-advances). The failure is logged as a
  failed result, no state invented; the user presses the key again.
- A failure surviving reconnect remains fatal-to-worker until
  AI-IMP-005's supervisor exists; IMP-005 builds its paired-teardown
  policy ON TOP of this per-use liveness primitive.
- Tests: transport fixture with a test clock proving the command
  role stays viable across a simulated timeout interval; a
  double-execution guard test proving mutating commands are not
  retried. The idle role's in-flight future is never cancelled by
  liveness machinery.
- Live acceptance for any ticket claiming song-transition behavior
  must include a QUIET SOAK exceeding 60 s before a natural
  transition — the class of failure fixtures cannot see.

Refresh coherence (ruled rev 0.6): a state refresh must produce a
COHERENT snapshot — never the new play state paired with the prior
song's metadata. Contract: issue =status= + =currentsong= as one
grouped command list (=command_list_ok_begin= with separated
responses) and validate =status.songid= against =currentsong.Id=;
on mismatch, discard the snapshot and retry. An equivalent
atomicity mechanism may substitute; "map the two latest responses"
may not. A test injecting a transition between the two logical reads
must prove no mixed =PlayerState= is emitted.

Incoherence bound (ruled rev 0.13, closing the IMP-002 verdict
note): THREE grouped refresh attempts, then a distinct typed
=SnapshotCoherenceExhausted= fault treated as an unusable connection
epoch — paired teardown, acknowledged clear, backoff (§5.5). Fixture
proves exactly three attempts and supervisor routing. A rev 0.10
liveness reconnect that succeeds internally stays transparent; only
a failure surviving its one retry enters paired teardown.

*** 5.1.1 Song identity (ruled rev 0.6)

One ambiguous "identity" field is forbidden; =PlayerState= carries
TWO identities with distinct contracts:

- OCCURRENCE identity — MPD queue =songid= (=Option=; =None= = no
  current song). Distinguishes duplicate queue entries of the same
  URI; stable while the song stays in the queue; explicitly NOT
  preserved across MPD restarts. Used for state transitions and
  same-song suppression within a connection epoch.
- MEDIA key — the song URI (file path). Durable across
  reconnect/restart; the artwork cache key (§5.3, AI-IMP-004) and
  the reconnect same-art reasoning (§5.5, AI-IMP-005) use THIS, and
  must never assume queue =songid= durability.

Fixture coverage required: duplicate queue entries sharing one URI
(distinct occurrences, same media key), and a queue-id change across
restart/reload (same media key, new occurrence).

** 5.2 Remote commands
toggle/play/pause/next/previous handlers translate to MPD commands on
the command connection. The macOS shim (§4) disables the playback
position capability so no phantom scrubber is advertised (rev 0.3).

Adapter publication contract (rev 0.4, verified against souvlaki
source): souvlaki's macOS =set_metadata= builds a NEW dictionary and
assigns it wholesale — it does not merge — so a metadata-only publish
silently drops elapsed/playback keys. Therefore =publish= takes a
coherent FULL =PlayerState= snapshot at the adapter boundary, and on
macOS every metadata/artwork-phase publish restores playback state
and elapsed position afterward. Call order is test-asserted.

Clearing contract (rev 0.4; refined rev 0.8): souvlaki's async
artwork load applies only if its captured =GLOBAL_METADATA_COUNTER=
still matches, and the native nil assignment does NOT advance that
counter — so bare nil can be resurrected by an in-flight art load.
=clear()= therefore first advances the generation
(=set_metadata(MediaMetadata::default())=, which starts no new art
work), THEN assigns nil — and (rev 0.8) does ONLY that: =clear()=
keeps the controls ATTACHED. The spike's literal sequence included
=detach()=, which in production would drop all remote handlers on
every disconnect/no-song clear and force a reattach that re-enables
the position command. Attachment/detachment is a separate
adapter-lifetime operation; EVERY attach calls souvlaki first, then
immediately disables =changePlaybackPositionCommand= through the
shim. Production shim/adapter methods return typed errors, never the
spike's =assert!=/=expect=. Spy tests assert both ordered sequences
(attach: souvlaki-attach → disable-position; clear:
generation-advance → nil, no detach). The delayed-art fake tests the
generation-advance seam.

Remote-command state loop (ruled rev 0.8, from the §8 spike
finding): on every SUCCESSFUL remote command the worker immediately
performs a coherent =refresh()= and publishes the resulting FULL
=PlayerState= — never waiting solely on the later idle notification,
or macOS keeps offering the stale action. A command ACK failure is
logged as a failed result and never invents optimistic state. The
bridge uses a local command enum of EXACTLY
toggle/play/pause/next/previous so out-of-scope souvlaki events
(seek/volume/stop) cannot leak into the MPD bridge.

Multi-artist projection (ruled rev 0.8): =PlayerState= keeps
repeated Artist tags as an ordered =Vec=; the platform boundary
projects them to souvlaki's single string by joining in source order
with =; = — empty vector maps to =None=. One rule for macOS and
Linux; mapping test uses the two-artist fixture shape.

** 5.3 Album art (amended rev 0.3)
=albumart=/=readpicture= on song change only (skip refetch when the
song is unchanged). MPD returns bytes; souvlaki takes a cover URL, so
the pipeline is: write bytes to a cache file ATOMICALLY (temp +
rename), publish the file URL, and suppress stale art — never publish
a URL before its bytes are durably written, never leave prior art
showing for a song without art.

Application media generation (ruled rev 0.11): souvlaki's counter
only guards a queued native load against a NEWER =set_metadata= —
it cannot know our media changed, so a stale fetch published as a
fresh call becomes the newest generation. Therefore the application
owns an artwork generation: at fetch completion the result is
publishable only if its media key is STILL CURRENT (else discarded),
and the artwork-phase publish combines the art with the LATEST
coherent =PlayerState=, never the state captured at fetch start.
Deterministic tests: delayed A→B discard; same-media state change
during a delayed fetch publishes latest state.

Artwork retention (ruled rev 0.11): every full publish carries the
current validated cover URL — souvlaki replaces the dictionary
wholesale (§5.2), so a same-media pause/elapsed publish without the
URL erases art. Same-key republishes preserve the URL with zero new
fetches (test-asserted); a NEW media key publishes explicitly
art-less metadata first, then the guarded artwork phase.

Artwork continuity (owner-ruled rev 0.12, from the M4 live gate —
supersedes the art-less-first transition default above): the card
must not visibly drop art it is about to re-show.
- Playback-only changes (pause/play/elapsed, same media key) must
  not pass through =set_metadata= — souvlaki's merge-path calls
  (=set_playback=/=set_playback_progress= copy the prior dictionary)
  preserve the artwork key natively. This refines, not reverses, the
  rev 0.8 full-snapshot contract: the ADAPTER still receives full
  snapshots; the macOS impl selects the merge path for
  playback-only diffs. Exact mechanism to round-1.
- Media-key changes HOLD the current artwork through the transition
  and swap only when the new fetch resolves: cache-hit same art →
  no visible change; different art → swap on arrival; resolved
  no-art → clear then. Prior art lingering for the fetch duration on
  an art-less track is accepted by owner ruling (the Music.app
  behavior). The rev 0.11 delayed-A→B discard guard still applies —
  holding is never publishing STALE art as new, it is not-yet-
  removing current art.
- True =clear()= (disconnect/no-song/shutdown) is unchanged —
  continuity never delays §5.2 clearing.

Continuity mechanism (ruled rev 0.13 — the rev 0.12 held-URL idea is
NOT executable: pinned souvlaki =set_metadata= assigns an art-less
dictionary immediately and loads the URL async, so a held URL
re-creates the M4 flicker; verified against the fork source):
- The nowplayd-owned souvlaki fork gains one minimal feature commit:
  the macOS metadata operation PRESERVES the current native artwork
  key while a non-null cover URL loads, atomically replaces it only
  after the guarded load completes, and removes it synchronously
  when the resolved publication has no cover. The existing global
  generation guard is kept. 007 pins that new immutable revision.
  MediaPlayer ownership stays in souvlaki; the §4 project shim stays
  two-method (§4 unamended). Fork branch pushed to
  =animegolem/souvlaki= under the owner's range authorization; the
  fork diff is part of wave review.
- Continuity contract is OBSERVABLE, not no-op: acceptance is "no
  intermediate art-less native state." Same-album tracks have
  different media keys and URLs, so a swap of an identical image is
  visually continuous — no content-identity subsystem. Spy/fork
  tests assert the prior artwork key remains present until
  replacement.
- Publication intent (rev 0.13): the worker selects an explicit
  intent — =FullMetadata= (initial publish, media/metadata/duration
  change, artwork resolve, resolved no-art) vs =PlaybackOnly=
  (same-media playback/elapsed-only). Occurrence-only changes with
  no projected-field delta make NO platform call (ruled; never
  accidentally full-metadata). True clear stays a separate
  operation, never a continuity publish.
- Merge-path edge (verified): souvlaki updates elapsed only for
  Playing/Paused with =Some(progress)=; Stopped or absent progress
  leaves a stale elapsed key. Those cases route through the
  art-preserving full path. Tests cover Playing/Paused with
  progress, Stopped, and absent progress.

Fairness mechanics (rev 0.11, sharpening rev 0.4): one artwork chunk
per worker scheduling turn; pending remote commands and state
refreshes are drained before the next chunk. The ordering
=chunk N → remote command → coherent refresh/full publish →
chunk N+1= is test-asserted.

Cache and decoder contract (ruled rev 0.11):
- Compressed size cap 10 MiB, enforced before allocation from the
  declared binary =size=.
- Accepted formats v1: JPEG and PNG, validated by decoding via the
  =image= crate with a dimension bound of 8192×8192; anything else
  (or corrupt bytes) is an explicit no-art publish plus a typed,
  logged artwork failure — never a souvlaki URL.
- Cache filename: SHA-256 of the media key (lowercase hex, =sha2=
  crate) + extension by validated format — deterministic and
  path-safe; no implementation-defined hasher.
- File URLs built with =url::Url::from_file_path= — never string
  concatenation.
- Durable-write sequence: same-directory temp → complete write →
  file sync → atomic rename → publish.
- Retention keeps current + previous files while souvlaki's load is
  asynchronous.

MPD binary assembly and fallback (ruled rev 0.11): the assembler
requires a stable declared size once bytes flow, uses checked offset
arithmetic, rejects zero-progress/truncated/overrun responses, and
completes only at exactly the declared length. Fallback
classification is narrow: =albumart= not-found → try =readpicture=;
an EMPTY successful =readpicture= means no art. Auth, permission,
malformed-response, and exhausted-transport failures are NOT "no
art" — logged, nonfatal per FR-8, and a transport failure surviving
the rev 0.10 single retry stays fatal-to-worker until IMP-005, never
silently demoted to an artwork miss. Integration fixture: transport
drop at a nonzero offset proves one reconnect/re-auth, the same
offset reissued once, bytes neither duplicated nor truncated.

Safety boundary (ruled rev 0.4, superseding the rev 0.3 claim that a
verified-written file suffices — a durable file can still hold
undecodable bytes; PIN REPLACED rev 0.9): souvlaki is pinned to the
nowplayd-owned fork =animegolem/souvlaki= revision
=ba2bf7653ace6ae22880ee7eeed623fee938cacf=. History: rev 0.4 pinned
upstream =436a5aed= for its nil-image guard, but that merge commit
DOES NOT COMPILE on macOS (three stale Cocoa =nil= references over
the raw-pointer backend, E0425; found live by the IMP-003 sitting,
reproduced from a clean fetch). The fork commit is upstream
=436a5aed= plus exactly the three-line raw-pointer fix
(=is_null()= / =null_mut()=), verified compiling from a clean fetch.
The same fix is offered upstream as Sinono3/souvlaki#79; if merged,
a future revision may return the pin to upstream. Invalid-image
fixture coverage is required at our boundary regardless. Cached-art
reuse (e.g. on reconnect) verifies the cached path still exists and
decodes; unchanged song identity alone is not sufficient.

** 5.4 Packaging
=LSUIElement= app bundle (no Dock icon) so Control Center presents it
properly; launchd user agent for start-at-login/keep-alive. Install
and update are idempotent; uninstall is documented (rev 0.3, §11
FR-9).

Logging (ruled rev 0.4; owner ruled rev 0.13): launchd's
=StandardOutPath=/=StandardErrorPath= redirect only — launchd
provides NO rotation. v1: tracing writes to STDERR in all modes and
=StandardErrorPath= owns the production file — no second app-managed
file writer. The immutable =mpd_protocol=off= directive is applied
AFTER user verbosity and cannot be overridden by any route (§11
FR-7). Rotation/unified logging remain future work (§9).

Config schema (ruled rev 0.13): TOML keys and env names are exact —
=NOWPLAYD_MPD_ADDRESS=, =NOWPLAYD_MPD_PASSWORD=,
=NOWPLAYD_CACHE_DIR=, =NOWPLAYD_LOG_LEVEL= — with ONE address
syntax unambiguously distinguishing TCP from unix socket. Missing
file = defaults; malformed present file = loud startup failure.
Config and source-report types have redacted =Debug=.

Supervision split (ruled rev 0.13): launchd handles PROCESS failure
only; the §5.5 supervisor owns MPD outages in-process forever.
Plist: =KeepAlive = { SuccessfulExit = false; }= plus an explicit
=ThrottleInterval= — clean signal exit 0 does not relaunch, a crash
does; KeepAlive implies RunAtLoad. Install/update PREFLIGHTS the
config before bootstrap so a malformed installed config cannot enter
a throttled restart loop.

The =org.nowplayd.*= dev identities were temporary.

Icon (rev 0.13): =packaging/nowplayd.icns= ships in-repo — interim

** 5.5 Lifecycle failure matrix (added rev 0.4)

Paired connection ownership: both connections are established and
authenticated as one transaction; the daemon enters Connected only
after both plus the initial full refresh succeed. Then:

- Transport-level failure (EOF, I/O error, malformed protocol) on
  EITHER role tears down both, clears Now Playing once, and begins
  backoff.
- MPD command-level ACK errors (no permission, no next song, …) log
  the command failure but do NOT tear down a healthy pair and do NOT
  clear.
- Backoff resets only after a defined healthy interval (not on bare
  socket handshake), so a flapping MPD cannot cycle at the 1 s floor.
- Cache reuse on reconnect revalidates per §5.3.

All four cases are covered by fake-connection lifecycle tests.

Typed classification (rev 0.13): =Command= ACK is the SOLE
healthy-pair failure class. Exhausted I/O/EOF AND malformed
protocol/mapping errors (=UnexpectedFrameCount=/=UnexpectedFields=/
=MissingField=/=InvalidField= — today neither transport nor ACK)
tear down the pair. A mutating transport failure BOTH emits the
typed failed command outcome (never retried) AND surfaces a
lifecycle fault. Typed errors are preserved through every worker
seam (idle/artwork/refresh channels) until the supervisor
classifies them — no stringification before classification.

Acknowledged clear (rev 0.13): platform mutation is
main-thread-owned, so the supervisor issues a production clear
REQUEST with a one-shot acknowledgement and waits for it before the
first backoff sleep and before clean exit; platform clear failure is
terminal and reported honestly. SIGTERM/SIGINT route through this
path and exit 0; other winit exits clear exactly once.

Artwork epoch invalidation (rev 0.13): disconnect, no-song, and
shutdown call =invalidate_epoch()= — advance the application art
generation, cancel pending logical work, clear held URL/key, and
make all outstanding job completions stale (tagged results
discarded deterministically; blocking jobs need not be
force-cancelled). Reconnect observes from an empty epoch and re-runs
cache lookup/decode. The idle task's join handle is owned and
aborted/awaited on every pair teardown so no stale idle role
survives a reconnect. 007's hold policy applies ONLY to connected
media→media transitions — never to disconnect/no-song/shutdown.

Deterministic timing (rev 0.13): injectable monotonic clock,
sleeper, and RNG. Nominal backoff 1,2,4,8,16,30,30… s with equal
jitter in [nominal/2, nominal]; 30 s is a hard cap. Reset only on a
successful coherent refresh at/after 30 s continuously connected —
never on handshake or quiet alone. Tests assert bounds without
wall-clock sleeps.

005→006 interface (rev 0.13): the supervisor accepts runtime inputs
(=ConnectionConfig=, cache root, event/log sink) by injection with
defaults at the call site — 005 keeps the interim typed-outcome
stderr sink; 006 supplies parsed config and replaces ONLY the sink
with tracing, never rewriting the supervisor API.

* 7. Acceptance criteria (amended rev 0.3)

- Media keys (toggle/next/prev) control MPD with subjectively
  immediate response, daemon running, any or no frontend open.
- Metadata and play/pause state correct in Control Center within
  1 s of the MPD event.
- Artwork correct within 3 s for the reference fixture: a JPEG
  ≤ 1.5 MB at ≥ 1000×1000 embedded in the test track.
- TRUE clearing (nil =nowPlayingInfo=): on MPD disconnect, on empty
  queue/no current song, and on graceful daemon shutdown.
- MPD restart: automatic reconnect with backoff; cleared while
  disconnected.
- Clean-clone install via one documented command; survives
  logout/login; re-running install is a no-op; uninstall documented.
- All three cargo gates pass.
- Human-test scripts state competing-player preconditions (§4).
  (Rev 0.4 mandated an UNCONTESTED quit-everything baseline distinct
  from observational arbitration runs; SUPERSEDED rev 0.6, folding
  the rev 0.5 §8 ruling: the macOS surface is a multi-session picker,
  so competing sessions are the NORMAL test environment and
  concurrent-session evidence is the stronger form — later acceptance
  tickets must not require quitting other players. Arbitration
  characterization (which card is default/focused across Music.app
  state changes) remains queued as optional enrichment and cannot
  fail a ticket; no "ownership regain" transition is required.)

* 11. Functional requirements (normative; added rev 0.3)

Stable clauses; tickets and epics cite these, never redefine them.

- FR-1 :: The daemon shall connect to MPD at a configurable address
  (default =localhost:6600=, unix sockets supported) and track
  playback via =idle player mixer options= on a dedicated idle
  connection (§5.1).
- FR-2 :: The daemon shall publish title, artist, album, duration,
  elapsed position, and play/pause state to macOS Now Playing on
  every relevant change, within the §7 bound.
- FR-3 :: The daemon shall register handlers for
  toggle/play/pause/next/previous remote commands, translate them to
  MPD commands, and DISABLE the playback-position capability via the
  §4 shim.
- FR-4 :: The daemon shall fetch album art via
  =albumart=/=readpicture=, publish it through the §5.3 atomic cache
  pipeline, and skip refetch when the song is unchanged.
- FR-5 :: The daemon shall truly clear Now Playing (nil
  =nowPlayingInfo= via the §4 shim) on MPD disconnect, on no current
  song, and on graceful shutdown; and shall reconnect with backoff
  after connection loss.
- FR-6 :: The project shall produce an =LSUIElement= app bundle and a
  launchd user agent plist; install/update idempotent, uninstall
  documented (with FR-9).
- FR-7 :: Configuration: zero-config default; TOML config file for
  persistent use; environment variable overrides take precedence
  (development/testing). (Amended rev 0.4:) a TOML-stored MPD
  password is a documented plaintext threat boundary — install/docs
  require owner-only file permissions, and the value is redacted
  from every log path. (Amended rev 0.7 — verified: =mpd_protocol=
  1.0.3 instruments =AsyncConnection::send/command= with
  =tracing::instrument(skip(self))=, recording the =Command= via
  Debug over its rendered bytes, i.e. =password <secret>=:) the
  tracing subscriber PERMANENTLY disables the =mpd_protocol= target —
  no environment verbosity setting, including the most verbose
  permitted, may re-enable it; a capture test proves a sentinel
  password never appears under that maximum configuration.
  Application logs record authentication success/failure only, never
  the command or credential. Authentication stays isolated in one
  private helper with no command logging of its own.
- FR-8 :: Observability: the daemon shall log non-secret startup
  configuration, connect/reconnect transitions, remote-command
  receipt and result, and artwork failures. (Amended rev 0.8 —
  interim seam until IMP-006:) command outcomes are TYPED values;
  =main= emits them via the current stderr record, and IMP-006
  replaces only the sink with =tracing=. Tests assert the semantic
  outcomes, never captured stderr text.
- FR-9 :: Install/update shall be idempotent and uninstall shall be a
  documented path that removes the bundle, the launchd agent, and
  cached artwork.
